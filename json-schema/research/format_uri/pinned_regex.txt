THE CANDIDATE PINNED URI CHECK (RFC 3986 URI, scheme REQUIRED).

This is the *body* of the regex (no start/end anchors). Each runtime wraps it in
its own portable full-input anchors (see per-runner notes): Go/JS `^...$` with no
multiline; Python `\A...\Z`; Java/.NET/Ruby `\A...\z`. The body is ASCII-only,
uses only character classes + alternation + `*`/`?` quantifiers, has NO
lookaround / backreferences / inline flags, so it compiles under the Rust
`regex` crate (the load-time gate) and is in the RE2 / regular family every
target's engine accepts.

Components (spaces added for readability; the emitted pattern has none):

  scheme     : [A-Za-z][A-Za-z0-9+.-]*
  pct        : %[0-9A-Fa-f][0-9A-Fa-f]
  userinfo   : (?:[A-Za-z0-9._~!$&'()*+,;=:-]|%[0-9A-Fa-f][0-9A-Fa-f])*
  host       : one of
                 IP-literal  : \[IPV6\]                     (IPv6)   -- SEMANTIC
                              | \[v[0-9A-Fa-f]+\.[A-Za-z0-9._~!$&'()*+,;=:-]+\]  (IPvFuture) -- permissive
                 reg-name/IPv4 : (?:[A-Za-z0-9._~!$&'()*+,;=-]|%[0-9A-Fa-f][0-9A-Fa-f])*
               where IPV6 is the RFC 4291 IPv6 grammar (full, ::-compressed, and
               IPv4-tail forms) spliced in VERBATIM from the pinned `ipv6` format
               check (research/format_conformance/) so the two checks agree byte-
               for-byte on what a valid IPv6 address is. `http://[zzzz]`,
               `http://[1::2::3]` (double `::`), and `http://[1:2:3:4:5:6:7:8:9]`
               (too many groups) are now REJECTED; `http://[2001:db8::1]`,
               `http://[::1]`, and IPv4-tail `http://[::ffff:192.0.2.1]` PASS.
  port       : [0-9]*
  authority  : (?:USERINFO@)?HOST(?::PORT)?
  pchar      : (?:[A-Za-z0-9._~!$&'()*+,;=:@-]|%[0-9A-Fa-f][0-9A-Fa-f])
  segment    : PCHAR*
  segment-nz : PCHAR+     (non-zero-length)
  path-abempty : (?:/PCHAR*)*          (used after //authority)
  path-absolute: /(?:PCHAR+(?:/PCHAR*)*)?   (starts with / but not //)
  path-rootless: PCHAR+(?:/PCHAR*)*         (no leading /, used when no authority)
  path-empty   : (empty)
  query      : (?:PCHAR|[/?])*
  fragment   : (?:PCHAR|[/?])*

  hier-part  : (?://AUTHORITY PATH-ABEMPTY) | PATH-ABSOLUTE | PATH-ROOTLESS | (empty)

  URI        : SCHEME : HIER-PART (?:\?QUERY)? (?:#FRAGMENT)?

FIDELITY LIMITS (documented, deliberate):
  * IPv6 IP-literal host is SEMANTIC: the bracketed bytes must form a valid RFC
    4291 IPv6 address. The check reuses the pinned `ipv6` format grammar verbatim
    (research/format_conformance/), bracket-wrapped, so the URI check and the
    standalone `ipv6` check agree byte-for-byte. `http://[zzzz]` (bad hex),
    `http://[1::2::3]` (two `::`), and `http://[1:2:3:4:5:6:7:8:9]` (nine groups)
    are rejected. The grammar is large and alternation-heavy but stays RE2-safe
    and compiles under the Rust `regex` crate and every other target engine.
  * IPvFuture IP-literal (`\[v...\]`) stays PERMISSIVE/structural: it checks
    bracket + `v` + hex + `.` + allowed byte class, not any deeper semantics.
    (RFC 3986 leaves IPvFuture's payload version-defined; no fixed grammar.)
  * reg-name does NOT reject an all-numeric-but-invalid IPv4 (e.g. 999.1.1.1);
    RFC 3986 lets such a string be a reg-name anyway, so this is actually faithful.
  * No enforcement that path after `//authority` is empty-or-absolute beyond the
    grammar (handled by path-abempty structure).
  * `%` is ONLY accepted as part of `%HEXDIG HEXDIG`; a bare or truncated `%`
    is rejected (faithful to pct-encoded).
  * ASCII only: any non-ASCII byte (IRI territory) is rejected (faithful to uri).
